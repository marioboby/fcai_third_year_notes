The plan for lecture two is to address the curse of dimensionality—a critical challenge in building generative models for complex data sets like images and text.

  

## The Curse of Dimensionality

Generative models aim to learn an unknown data distribution, $P_{data}$, from a set of examples to generate new, similar data points. The difficulty lies in representing probability distributions over high-dimensional spaces.

- For a single discrete random variable (e.g., a coin flip), only one parameter is needed.
    
      
    
- For a categorical random variable with $M$ outcomes, $M-1$ parameters are required.
    
    ![Pasted image 20260929225800.png](/img/user/imgs/Pasted%20image%2020260929225800.png)  
    
- For an image, each pixel is a random variable. A color pixel ($256 \times 256 \times 256$ possible values) needs millions of parameters.
    
      
    
- Even for a simple $N$-pixel black-and-white image, the joint probability distribution requires $2^N - 1$ parameters to assign a probability to every possible combination. This geometric series causes an exponential blowup, resulting in a state space larger than the number of atoms in the universe for even small values of $N$. Storing and learning these parameters is computationally impossible without assumptions.
    
      
    

## Strategies to Simplify the State Space

To make progress, we must make conditional independence assumptions about how random variables relate to each other.

  

### 1. Full Independence Assumption

Assume all variables (e.g., pixels) are entirely independent. The joint distribution becomes a product of individual marginal distributions.

  

- **Pros:** Drastically reduces parameters from $2^N$ to $N$.
    
      
    
- **Cons:** Way too strong of an assumption. Choosing pixel values independently at random without looking at neighboring pixels cannot capture the structure of real-world data like handwritten digits.
    
      
    
![Pasted image 20260929233202.png](/img/user/imgs/Pasted%20image%2020260929233202.png)
### 2. Autoregressive Models and the Chain Rule

Use the chain rule of probability to factorize a joint distribution exactly: $P(X_1, X_2, X_3) = P(X_1) \times P(X_2\vert{}X_1) \times P(X_3\vert{}X_1, X_2)$.

  

- This approach is fully general and requires no assumptions, but it does not save parameters on its own. The conditional distributions become increasingly complex (e.g., $P(X_3\vert{}X_1, X_2)$ needs $4$ parameters, the next needs $8$, etc.).
    
      
    
- To get savings, we can apply a Markov assumption (conditional independence). For example, assume the next word depends _only_ on the previous word, ignoring earlier context: $P(X_3\vert{}X_1, X_2)$ simplifies to $P(X_3\vert{}X_2)$.
  
	- Full Chain Rule: $1 + 2 + \dots + 2^{n-1} = 2^n - 1$ parameters.
    
	- Markov Assumption ($X_{i+1} \perp X_{1,\dots,i-1} \vert{} X_i$): Exactly **$2n - 1$** parameters.
    
      
    
- While Markov assumptions save parameters linearly ($O(N)$), they are often too simplistic for complex sequences like language, where broader context matters.
    
      
    

### 3. [[3rd Year/Cognitive Science/Before Mid/Lecture 4 - Bayesian Networks\|Bayesian Networks]] (Probabilistic Graphical Models)

A more general way to handle conditional independence is using Bayesian networks.

  

- A Bayesian network is a Directed Acyclic Graph (DAG) where nodes are variables and edges define dependencies (parents).
    
      
    
- The joint distribution is the product of the conditional probability of each variable given its parents.
    
      
    
- **Example:** A student's grade depends on the exam's difficulty and the student's intelligence. The SAT score depends only on intelligence. These local dependencies are much easier to represent than a full joint distribution table.
    
      
    
- The more parents a node has, the more parameters are needed. A dense graph is expressive but computationally heavy; a chain graph (one parent per node) is the simple Markov model.

## Discriminative vs. Generative Models

Let's explore how these concepts apply to a task like spam classification to understand the distinction between discriminative and generative approaches.

  

### The Generative Approach (e.g., Naive Bayes)

- Models the full joint distribution $P(X, Y)$ using chain rule: $P(Y) \times P(X\vert{}Y)$.
    
      
    
- **Naive Bayes Assumption:** The features (words in the email) are conditionally independent given the label (spam/not spam).
    
      
    
- **Pros:** Can reason about inputs (e.g., imputing missing words) because it models the relationship between features.
    
      
    
- **Cons:** The conditional independence assumption is often false. The model double-counts evidence if two words always appear together (e.g., "bank" and "account") because it assumes they are independent signals.
    
      
    

### The Discriminative Approach (e.g., Logistic Regression)

- Models only the conditional distribution $P(Y\vert{}X)$.
    
      
    
- It doesn't care about modeling the distribution of features $P(X)$ because it assumes the features will always be provided at test time.
    
      
    
- Instead of a lookup table for $P(Y\vert{}X)$ (which would have $2^N$ rows), it assumes a specific functional form. Logistic regression uses a linear combination of features passed through a sigmoid function.
    
      
    
- **Pros:** It doesn't make the strong conditional independence assumption of Naive Bayes. It can adjust weights (setting one to zero) to avoid double-counting correlated features. This weaker assumption often yields better practical performance.
    
      
    
- **Cons:** It cannot reason about its inputs. It cannot impute missing features because it never modeled the relationships between the $X$ variables. It also relies on the assumption that a linear relationship is sufficient, which may not hold true.
    
      
    
> [!TD;LR]
> 
> The fundamental difference between generative and discriminative models lies in the specific probability distributions they attempt to learn and the mathematical assumptions they make about the data.
> 
>   
> 
> ## Discriminative Models: Learning the Boundary
> 
> Discriminative models are designed exclusively to separate data into classes. They do not care how the data was created; they only care about drawing a boundary between different labels.
> 
>   
> 
> - **Mathematical Objective:** They model only the conditional distribution $P(Y\vert{}X)$. Given a set of features $X$ (like words in an email), they predict the probability of a label $Y$ (spam or not spam).
>     
>       
>     
> - **The Approach:** Because they assume the features $X$ will always be provided to them at test time, they completely ignore modeling $P(X)$—the distribution of the features themselves. Instead of building a massive lookup table for every possible feature combination, they assume a specific functional relationship (like a linear combination passed through a sigmoid function in Logistic Regression).
>     
>       
>     
> - **Strengths in Classification:** By ignoring $P(X)$, discriminative models avoid making rigid conditional independence assumptions about the features.
>     
>       
>     - **Example:** In spam classification, if the words "bank" and "account" always appear together, a logistic regression model can simply assign a weight of zero to one of them, effectively ignoring the redundant information.
>         
>           
>         
> - **Limitations:** They cannot reason about their inputs. If you provide a discriminative model with an image missing half its pixels, it cannot impute or hallucinate the missing values because it never learned the underlying structural relationships between the pixels themselves.
>     
>       
>     
> 
> ## Generative Models: Learning the Distribution
> 
> Generative models are data simulators. They attempt to learn the entire structural reality of the data so they can understand and recreate it.
> 
>   
> 
> - **Mathematical Objective:** They model the full joint distribution $P(X, Y)$, which can be factorized using the chain rule as $P(Y) \times P(X\vert{}Y)$. They must learn the probability of seeing a specific label _and_ the probability of seeing specific features given that label.
>     
>       
>     
> - **The Approach:** To handle the immense complexity of modeling every feature, they must make assumptions about how variables relate.
>     
>       
>     - **Example:** The Naive Bayes classifier makes a strong assumption that all features $X_i$ are conditionally independent given the label $Y$.
>         
>           
>         
> - **Strengths in Reasoning:** Because generative models understand $P(X)$, they can handle missing data gracefully. If variables are unobserved, a generative model can compute the probability of a label by **marginalizing** over the unseen variables.
>     
>       
>     
> - **Limitations:** The strict assumptions required to model the full distribution can hurt classification accuracy.
>     
>       
>     - **Example:** In the Naive Bayes spam classifier, because the model assumes the words "bank" and "account" are completely independent, it will treat seeing both words as two separate, compounding pieces of evidence. It "double counts" the evidence, which can lead to overconfident or incorrect predictions.
>         
> 
> ## Summary Comparison
> 
>
>
> |**Feature**|**Discriminative Models**|**Generative Models**|
> |---|---|---|
> |**Primary Goal**|Predict a label given data.|Understand how data is generated.|
> |**Probability Modeled**|Conditional: $P(Y\vert{}X)$|Joint: $P(X, Y)$ or $P(X)$|
> |**Handling Missing Data**|Fails or requires external imputation.|Can mathematically marginalize over missing variables.|
> |**Feature Correlation**|Handles correlated features well (e.g., Logistic Regression).|Often struggles with correlated features due to strict independence assumptions (e.g., Naive Bayes).|
> |**Example Models**|Logistic Regression, Support Vector Machines (SVMs), Traditional Neural Networks.|Naive Bayes, Variational Autoencoders (VAEs), Diffusion Models, Autoregressive Models (LLMs).|
## Deep Generative Models: Neural Networks Meet Chain Rule

The functional assumptions in logistic regression (linear combinations) are often too simple. Deep learning provides a solution.

  

- By replacing the direct linear mapping with hidden layers (non-linear transformations), neural networks can capture much more complex relationships between inputs and outputs.
    
      
    
- **Neural Autoregressive Models (e.g., Large Language Models):** These models use the chain rule factorization but replace the complicated conditional distributions (which would normally require massive lookup tables) with neural networks.
    
      
    
- Instead of storing every possible combination, a neural network is trained to predict the next word given the previous sequence. This relies on the assumption that a neural network can effectively capture these complex conditional relationships.
    
      
    

## Handling Continuous Variables

The same machinery applies when moving from discrete variables (probability mass functions) to continuous variables (probability density functions).

  

- Tables are impossible for continuous variables, so we must assume functional forms, such as Gaussian or uniform distributions.
    
      
    
- **Example: Mixture of Gaussians:** A simple Bayesian network with a discrete latent variable $Z$ and a continuous observable variable $X$. First, sample $Z$ (e.g., a coin flip). Then, sample $X$ from a specific Gaussian determined by $Z$. This provides a more flexible distribution than a single Gaussian.
    
      
    
- **Example: Variational Autoencoder (VAE):** This mixes Bayesian networks with neural networks. Sample a latent variable $Z$ from a simple Gaussian. Then, feed $Z$ through a neural network to output the mean and variance for a new Gaussian distribution, from which $X$ is sampled.
    
      
    

> [!Note]
> 
> To model the incredible complexity of the real world—from the millions of pixels in a photograph to the grammatical structure of a sentence—we must overcome the curse of dimensionality. Since we cannot store every possible state in a massive lookup table, we are forced to make assumptions. Do we assume variables are conditionally independent, as in Bayesian networks? Or do we assume that a deep neural network can discover the underlying functional relationships, as in autoregressive models? Every generative architecture we cover in this course is, at its core, a different strategy for placing these bets.
